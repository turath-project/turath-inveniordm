# Developer Guide: Integrating HOCR Annotation & Search Services

## 1. Goal

The primary objective of this work was to integrate two external Python Flask-based services into the main InvenioRDM Docker Compose environment:

1.  **Annotation Service:** Generates IIIF annotations (word boundaries) based on HOCR files for a specific book page.
2.  **Search Service:** Provides a IIIF Content Search API endpoint, allowing text search within the HOCR files of a book.

The goal was to make these services part of the standard `docker compose up` workflow, ensuring they could access necessary HOCR data and that the IIIF manifests generated by the `upload_book.py` script linked to these containerized services correctly.

## 2. Initial State

Before this integration, the system relied on:

*   **InvenioRDM:** Running via Docker Compose, managing records and serving files (PDFs, HOCR).
*   **Cantaloupe IIIF Image Server:** Running via Docker Compose, serving page images from PDFs.
*   **Annotation & Search Services:** Running as **separate, external** Python processes (e.g., `python app.py` on the host machine or another server).
*   **HOCR Data Access:** These external services were configured to read HOCR files directly from a **local filesystem path** (e.g., `./books/<book_id>/hocr/`), requiring HOCR data to exist both within the InvenioRDM record *and* on the local filesystem where the services ran.
*   **Manifest Linking:** The `upload_book.py` script generated IIIF manifests pointing to these external services using `http://localhost:5001` (search) and `http://localhost:5002` (annotations).

This setup was functional for local development but not robust or easily deployable.

## 3. The Plan

The integration plan involved the following steps:

1.  **Containerize Services:** Create Dockerfiles for the annotation and search Flask applications.
2.  **Integrate into Docker Compose:** Add service definitions for the annotation and search services to the project's `docker-compose.yml`.
3.  **Handle HOCR Data Access:** Devise a method for the containerized services to access the necessary HOCR files for the relevant books. The chosen initial approach was to use a **shared Docker bind mount** from the host.
4.  **Refactor Service Code:** Remove hardcoded paths and URLs from the Flask applications, making them configurable via environment variables.
5.  **Update Manifest Generation:** Modify `scripts/upload_book.py` to:
    *   Generate IIIF manifest URLs pointing to the containerized services (using Docker service names or proxied public URLs).
    *   Implement logic to copy HOCR files to the shared host directory (bind mount source) after successful upload to InvenioRDM.
    *   **(Correction Added Later)** Ensure the generated manifest file is uploaded with the correct key (`manifest.json`) instead of a temporary name.

## 4. Implementation Steps (How-To)

### 4.1. Creating Service Code Structure

*   Created a `services/` directory in the project root.
*   Created subdirectories for each service: `services/annotation_service/` and `services/search_service/`.
*   Placed the respective Flask application code into `app.py` files within these directories.

```bash
mkdir -p services/annotation_service
mkdir -p services/search_service
# (Copy/paste Flask code into services/annotation_service/app.py and services/search_service/app.py)
```

### 4.2. Refactoring Service Code

The original Flask `app.py` files contained hardcoded paths and URLs (e.g., reading HOCR from `os.getcwd()`, using `localhost:5001`/`localhost:5002`). This needed to be changed for containerization.

*   **HOCR Path:** Modified the code to read HOCR files from a fixed base path within the container, configured via an environment variable (`HOCR_BASE_DIR`), defaulting to `/hocr_data/books`.

    *Example Change (Conceptual):*
    ```python
    # Before:
    # hocr_dir = os.path.join(os.getcwd(), 'books', book_id, 'hocr')

    # After:
    HOCR_BASE_DIR = os.environ.get('HOCR_BASE_DIR', '/hocr_data/books')
    book_hocr_dir = os.path.join(HOCR_BASE_DIR, book_id, 'hocr')
    ```
*   **Service URLs:** Modified the code to construct internal and external URLs using base URLs provided by environment variables (e.g., `ANNOTATION_SERVICE_BASE_URL`, `SEARCH_SERVICE_BASE_URL`, `IIIF_SERVER_BASE_URL`).

    *Example Change (Conceptual):*
    ```python
    # Before:
    # annotation_list_id = f"http://localhost:5002/annotations/{book_id}/{page_identifier}/line"

    # After:
    ANNOTATION_SERVICE_BASE_URL = os.environ.get('ANNOTATION_SERVICE_BASE_URL', 'http://localhost:5002')
    annotation_list_id = f"{ANNOTATION_SERVICE_BASE_URL}/annotations/{book_id}/{page_identifier}/line"
    ```
*   **Configuration:** Added logging and made ports, SSL settings, and CORS origins configurable via environment variables.

### 4.3. Creating Dockerfiles

Created a `Dockerfile` in each service directory (`services/annotation_service/Dockerfile` and `services/search_service/Dockerfile`).

*Example Dockerfile (`services/annotation_service/Dockerfile`):*
```dockerfile
# Use an official Python runtime as a parent image
FROM python:3.9-slim

# Set the working directory in the container
WORKDIR /app

# Copy the requirements file into the container at /app
COPY requirements.txt .

# Install any needed packages specified in requirements.txt
RUN pip install --no-cache-dir -r requirements.txt

# Copy the current directory contents into the container at /app
COPY . .

# Make port 5002 available
EXPOSE 5002

# Define environment variable defaults
ENV PORT=5002
ENV FLASK_APP=app.py
ENV FLASK_RUN_HOST=0.0.0.0
ENV HOCR_BASE_DIR=/hocr_data/books
ENV ANNOTATION_SERVICE_BASE_URL=http://annotation-service:5002
ENV IIIF_SERVER_BASE_URL=http://nginx:80
ENV USE_SSL=false

# Run app.py when the container launches, listening on the specified PORT (Shell form for variable substitution)
CMD flask run --host=0.0.0.0 --port=$PORT
```

*   **Key Parts:**
    *   `FROM python:3.9-slim`: Uses a lightweight Python base image.
    *   `WORKDIR /app`: Sets the working directory inside the container.
    *   `COPY requirements.txt .`: Copies the dependency file.
    *   `RUN pip install ...`: Installs Python packages.
    *   `COPY . .`: Copies the service's Python code (`app.py`) into the container.
    *   `EXPOSE 5002`: Informs Docker that the container listens on this port.
    *   `ENV ...`: Sets default environment variables. Crucially, `ANNOTATION_SERVICE_BASE_URL` and `SEARCH_SERVICE_BASE_URL` use the Docker service names (`annotation-service`, `search-service`) for internal communication. `IIIF_SERVER_BASE_URL` assumes `nginx` is the proxy.
    *   `CMD flask run ...`: Specifies the command to run when the container starts, using the shell form (`flask run ... --port=$PORT`) to allow the `$PORT` environment variable to be correctly substituted.

### 4.5. Updating `docker-compose.yml`

Added the new services to the main `docker-compose.yml` file.

*Example Snippet:*
```yaml
services:
  # ... other services (cache, db, etc.) ...

  # Turath Annotation Service (HOCR-based)
  annotation-service:
    build:
      context: ./services/annotation_service # Build from the Dockerfile in this dir
    restart: "unless-stopped"
    ports:
      # Map container port 5002 to host port 5002 (accessible only locally)
      - "127.0.0.1:5002:5002"
    volumes:
      # Mount the host directory to the data path inside the container
      # NOTE: Assumes ./hocr_mount exists on the host!
      - ./hocr_mount:/hocr_data
    environment:
      - FLASK_DEBUG=1 # Enable debug mode for development
      - PORT=5002
      - HOCR_BASE_DIR=/hocr_data/books # Matches path in app.py
      - ANNOTATION_SERVICE_BASE_URL=http://annotation-service:5002 # Internal URL
      - IIIF_SERVER_BASE_URL=http://nginx:80 # Assumes nginx proxy
      - USE_SSL=false
      # Define allowed origins for CORS (adjust as needed)
      - CORS_ALLOWED_ORIGINS=http://localhost:3000,http://127.0.0.1:3000,http://localhost:8000,http://127.0.0.1:5000
    expose:
      - 5002 # Expose port internally

  # Turath Search Service (HOCR-based)
  search-service:
    build:
      context: ./services/search_service
    restart: "unless-stopped"
    ports:
      - "127.0.0.1:5001:5001" # Map internal 5001 to host 5001
    volumes:
      # Mount the same host directory
      - ./hocr_mount:/hocr_data
    environment:
      - FLASK_DEBUG=1
      - PORT=5001
      - HOCR_BASE_DIR=/hocr_data/books
      - SEARCH_SERVICE_BASE_URL=http://search-service:5001 # Internal URL
      - IIIF_SERVER_BASE_URL=http://nginx:80
      - USE_SSL=false
      - CORS_ALLOWED_ORIGINS=http://localhost:3000,http://127.0.0.1:3000,http://localhost:8000,http://127.0.0.1:5000
    expose:
      - 5001

# NOTE: The named volume 'hocr-data' was removed as we switched to a host bind mount
# volumes:
#   data:
#   images:
#   image_tiles:
#   # hocr-data: {} # Replaced by bind mount from host directory
```

*   **Key Parts:**
    *   `build: context: ...`: Tells Compose to build the image using the Dockerfile in the specified directory.
    *   `ports: - "127.0.0.1:5001:5001"`: Maps the container's port (right side) to a port on the host machine (left side), but only accessible via `127.0.0.1` on the host.
    *   `volumes: - ./hocr_mount:/hocr_data`: This is the **bind mount**. It maps the `./hocr_mount` directory from the host machine (where the `docker compose` command is run) to the `/hocr_data` directory inside the container. This allows the containerized services to read files placed in `./hocr_mount` by the `upload_book.py` script.
    *   `environment:`: Sets environment variables for the container, overriding defaults set in the Dockerfile if necessary.
    *   (Removed `volumes: hocr-data: {}` as the named volume is no longer used).

### 4.6. Updating `upload_book.py`

Modified the `scripts/upload_book.py` script in **three** main ways:

1.  **Manifest URL Generation:** Changed the hardcoded `localhost:500x` URLs to use a configurable public-facing base URL (currently hardcoded to `https://localhost` as a placeholder) and assumed standard proxy paths (`/annotations/`, `/search/`, `/autocomplete/`). This anticipates setting up the Nginx `frontend` service to proxy these requests.

    *Example Change (`_generate_manifest_content` method):*
    ```python

    # annotation_service_base = f"{service_protocol}://localhost:5002/annotations"
    # search_service_url = f"{service_protocol}://localhost:5001/search"
    # autocomplete_service_url = f"{service_protocol}://localhost:5001/autocomplete"
    # ...
    # "@id": f"{annotation_service_base}/{self.book_id}/p{page_label}/line",
    # ...
    # "@id": search_service_url,
    # ...

    search_service_proxy_url = f"{public_facing_base_url}/search/{self.book_id}"
    ```

2.  **HOCR File Copying:**
    *   Added a `--hocr-mount-point` command-line argument to specify the host directory used for the bind mount.
    *   Added logic in the `process()` method to copy the HOCR files (collected earlier in the script) to the specified mount point after the main file upload to InvenioRDM is successful. This uses the structure `<mount_point>/books/<book_id>/hocr/`, which matches what the services expect to read inside the container via `/hocr_data/books/<book_id>/hocr/`.

    *Added Logic Snippet (in `process()`):*
    ```python
    # (After upload_result = self.upload_files_to_record(...) )
    if not upload_result["success"]:
        # ... error handling ...
    else:
        # --- Copy HOCR files to mount point if specified ---
        if self.hocr_mount_point and files['hocr']:
            target_hocr_base = os.path.join(self.hocr_mount_point, 'books', self.book_id, 'hocr')
            logger.info(f"Copying {len(files['hocr'])} HOCR files to service mount point: {target_hocr_base}")
            try:
                os.makedirs(target_hocr_base, exist_ok=True)
                copied_count = 0
                for hocr_file_path in files['hocr']:
                    hocr_filename = os.path.basename(hocr_file_path)
                    dest_path = os.path.join(target_hocr_base, hocr_filename)
                    try:
                        shutil.copy2(hocr_file_path, dest_path)
                        copied_count += 1
                    # ... error handling for individual copy ...
                logger.info(f"Successfully copied {copied_count} HOCR files to {target_hocr_base}")
            except Exception as e:
                logger.error(f"Failed to create or copy HOCR files to {target_hocr_base}: {e}")
        elif self.hocr_mount_point:
            logger.info("HOCR mount point specified, but no HOCR files found...")
        # --- End HOCR copy ---
    # ... rest of process method (publish, etc.)
    ```

    *   **Solution:** Modified the `process` method (around line 1326) to save the generated manifest content explicitly as `manifest.json` in a temporary directory and then upload that specific file, ensuring the key used by Invenio matches the internal `@id`.

### 4.7. Building and Running

1.  **Create Host Mount Directory:** Ensure the directory specified for the bind mount exists on the host machine:
    ```bash
    mkdir -p ./hocr_mount
    ```
2.  **Build & Start:** Use Docker Compose to build the new service images and start the entire stack:
    ```bash
    docker compose up -d --build
    ```
3.  **Upload Book:** Run the `upload_book.py` script, providing the `--hocr-mount-point ./hocr_mount` argument:
    ```bash
    pipenv run python scripts/upload_book.py \
        --book-dir scripts_docs/books/history00872 \
        --api-url https://127.0.0.1:5000/api \
        --hocr-mount-point ./hocr_mount \
        --verbose \
        --no-verify-ssl \
        --skip-tiff # Or other flags as needed
    ```

## 5. Challenges & Troubleshooting

*(This section summarizes key challenges specific to this integration task. See `docs/learning/troubleshooting-cheatsheet.md` for a broader list)*

*   **HOCR File Access:** The primary challenge was ensuring the containerized annotation and search services could read the HOCR files associated with a specific book uploaded via `upload_book.py`.
    *   **Initial Idea (Rejected):** Directly mounting Invenio's internal `data` volume was complex due to Invenio's hashed file structure.
    *   **Chosen Solution:** Using a host bind mount (`./hocr_mount`) and modifying `upload_book.py` to copy the necessary HOCR files to this location after upload, using a predictable path (`books/<book_id>/hocr/`). The services then read from the corresponding path inside their containers (`/hocr_data/books/<book_id>/hocr/`).
*   **Nginx Proxy Configuration:** Ensuring the `frontend` Nginx service correctly proxied requests for `/annotations/`, `/search/`, and `/autocomplete/` to the internal service containers (`annotation-service:5002`, `search-service:5001`). Verified in `docker/nginx/nginx.conf`.
*   **Service Code Paths:** Modifying the Flask service code (`app.py`) to read HOCR files from the correct container path (`/hocr_data/books/...`) instead of hardcoded local paths.
*   **Manifest URL Generation:** Updating `upload_book.py` to generate URLs pointing to the Nginx proxy (`https://localhost/...`) rather than the internal service ports (`http://localhost:500x/...`) for links intended to be used by the browser/IIIF viewer.
*   **Docker CMD Syntax:** Ensuring the `CMD` instruction in the service Dockerfiles used the shell form (`CMD flask run ... --port=$PORT`) rather than the exec form (`CMD ["flask", "run", ..., "--port=$PORT"]`) to allow environment variable substitution for the port.

## 6. Conclusion

Integrating external Flask services into the Docker Compose stack involved containerizing the applications, setting up a shared data mechanism (host bind mount + script copy step), configuring Nginx for proxying, and updating the services and the upload script to use configurable paths and URLs. This provides a more robust and deployable solution compared to running the services externally.
