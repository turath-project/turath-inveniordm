## Overview

The IIIF (International Image Interoperability Framework) integration in Zenodo RDM enables high-resolution image viewing with rich metadata. The workflow consists of:

1. User uploads an image file to a record
2. File is stored in the system's storage backend
3. When requested, a IIIF manifest is generated for the record
4. Images are served via an IIPImage server for deep zoom functionality

## File Upload Workflow

When a user uploads a file to a record in Zenodo RDM, the following happens:

1. The file is uploaded through the web interface or API
2. Zenodo RDM's file processing pipeline handles the file:
   - File is stored in the configured storage backend
   - Metadata about the file is recorded in the record's metadata
   - File becomes available through the record's files API

## File Storage Structure

Files in Zenodo RDM are stored according to this pattern:

```
data/
└── records/
    └── <record_id>/
        └── files/
            └── <filename>
```

For IIIF to work correctly, image files must be converted to PTIF (Pyramid TIFF) format and stored where IIPImage server can access them:

```
data/
└── images/
    └── private/
        └── <record_id>/
            └── <filename>.ptif
```

Our `setup_iiif_for_record.sh` script automates this process by:
1. Downloading the file from the record
2. Converting it to PTIF format
3. Copying it to the correct location

## Manifest Generation

IIIF manifests are generated on-demand when a client requests the manifest URL:

```
/api/iiif/record:<record_id>/manifest
```

The key components involved are:

### 1. IIIFResource Class

Located in `.venv/lib/python3.9/site-packages/invenio_rdm_records/resources/iiif.py`, this class handles IIIF API requests, including manifest generation:

```python
@cross_origin(origin="*", methods=["GET"])
@with_iiif_content_negotiation(IIIFManifestV2JSONSerializer)
@iiif_request_view_args
@response_handler()
@proxy_pass.__func__
def manifest(self):
    """Manifest."""
    return self._get_record_with_files().to_dict(), 200
```

### 2. IIIFManifestV2Schema

Located in `.venv/lib/python3.9/site-packages/invenio_rdm_records/resources/serializers/iiif/schema.py`, this schema defines how to serialize a record into a IIIF manifest:

```python
class IIIFManifestV2Schema(Schema):
    """IIIF manifest schema."""

    class Meta:
        """Marshmallow meta class."""

        include = {
            "@context": fields.Constant(
                "http://iiif.io/api/presentation/2/context.json"
            ),
            "@type": fields.Constant("sc:Manifest"),
            "@id": fields.String(attribute="links.self_iiif_manifest"),
        }

    label = fields.String(attribute="metadata.title")
    metadata = fields.Method("get_metadata")
    description = fields.String(
        attribute="metadata.description",
        default=_("Manifest generated by InvenioRDM"),
    )
    license = fields.Method("get_license")

    sequences = SelfList(SelfNested(IIIFSequenceV2Schema))
```

### 3. Record and File Serialization

The system reads the record and file metadata, then uses the IIIF schema to generate a manifest in the IIIF Presentation API format.

### Manifest Structure

A simplified IIIF manifest looks like:

```json
{
  "@context": "http://iiif.io/api/presentation/2/context.json",
  "@type": "sc:Manifest",
  "@id": "https://example.org/iiif/record:123/manifest",
  "label": "Record Title",
  "metadata": [
    {"label": "Publication Date", "value": "2023-01-01"}
  ],
  "sequences": [
    {
      "@id": "https://example.org/iiif/record:123/sequence/default",
      "canvases": [
        {
          "@id": "https://example.org/iiif/record:123/canvas/image.jpg",
          "label": "image.jpg",
          "width": 1200,
          "height": 800,
          "images": [
            {
              "@id": "https://example.org/iiif/record:123/annotation/image.jpg",
              "@type": "oa:Annotation",
              "motivation": "sc:painting",
              "resource": {
                "@id": "https://example.org/iiif/record:123:image.jpg/full/full/0/default.jpg",
                "@type": "dctypes:Image",
                "format": "image/jpeg",
                "width": 1200,
                "height": 800,
                "service": {
                  "@context": "http://iiif.io/api/image/2/context.json",
                  "@id": "https://example.org/iiif/record:123:image.jpg",
                  "profile": "http://iiif.io/api/image/2/level1.json"
                }
              },
              "on": "https://example.org/iiif/record:123/canvas/image.jpg"
            }
          ]
        }
      ]
    }
  ]
}
```

## Customizing Manifests

To customize how manifests are generated, you can modify the IIIF schema classes. Here are some common customization scenarios:

### 1. Adding Additional Metadata Fields

To add more metadata fields to the manifest, modify the `get_metadata` method in `IIIFManifestV2Schema`:

```python
def get_metadata(self, obj):
    """Generate metadata entries."""
    metadata = [
        {
            "label": _("Publication Date"),
            "value": obj["metadata"]["publication_date"],
        }
    ]
    
    # Add creator information if available
    if "creators" in obj["metadata"] and obj["metadata"]["creators"]:
        creators = [creator["person_or_org"]["name"] for creator in obj["metadata"]["creators"]]
        metadata.append({
            "label": _("Creator"),
            "value": "; ".join(creators)
        })
        
    return metadata
```

### 2. Changing the Canvas Sorting

To change how canvases (images) are sorted in the manifest, modify the `sortcanvases` method:

```python
@post_dump
def sortcanvases(self, manifest, many, **kwargs):
    """Sort files by key."""
    # Sort by filename in reverse order
    manifest["sequences"][0]["canvases"].sort(key=lambda x: x["@id"], reverse=True)
    return manifest
```

### 3. Adding Thumbnail Information

To add thumbnail information to the manifest, you can add a new field to the `IIIFManifestV2Schema`:

```python
thumbnail = fields.Method("get_thumbnail")

def get_thumbnail(self, obj):
    """Get thumbnail for manifest."""
    # Find first image file
    files = obj.get("files", {}).get("entries", {})
    for key, file in files.items():
        if file["ext"] in current_app.config["RDM_IIIF_MANIFEST_FORMATS"]:
            return {
                "@id": f"{file['links']['iiif_base']}/full/100,/0/default.jpg",
                "service": {
                    "@context": "http://iiif.io/api/image/2/context.json",
                    "@id": file["links"]["iiif_base"],
                    "profile": "http://iiif.io/api/image/2/level1.json",
                }
            }
    return missing
```

### 4. Customizing for Specific Record Types

You can customize manifests for specific record types by subclassing the schema and implementing custom logic:

```python
class CustomIIIFManifestV2Schema(IIIFManifestV2Schema):
    """Custom IIIF manifest schema for specific record types."""
    
    def get_metadata(self, obj):
        """Generate custom metadata based on record type."""
        metadata = super().get_metadata(obj)
        
        # Add specific metadata for books
        if obj["metadata"].get("resource_type", {}).get("id") == "book":
            if "subjects" in obj["metadata"]:
                subjects = [s["subject"] for s in obj["metadata"]["subjects"]]
                metadata.append({
                    "label": _("Subjects"),
                    "value": subjects
                })
        
        return metadata
```

## Testing and Verification

After making changes to the manifest generation, you should test that the changes work correctly:

### 1. Check that a record has IIIF enabled

```bash
cd scripts/AlA
make check-iiif RECORD=123
```

### 2. Examine the manifest JSON

```bash
curl -k -H "Accept: application/ld+json" "https://127.0.0.1:5000/api/iiif/record:123/manifest" | jq
```

### 3. Test with a IIIF viewer

Access the record in a browser and check that the images display correctly in the viewer.

## Common Issues

### Missing Images in Manifest

If images are missing from the manifest:

1. Check that the files exist in the record
2. Verify that the file formats are in `RDM_IIIF_MANIFEST_FORMATS` config
3. Ensure the files have proper metadata (width and height)

### Incorrect URLs

If image URLs are incorrect:

1. Check the base URL configuration in your app
2. Verify that the URL generation in the schema is correct

### Performance Issues

If manifest generation is slow:

1. Consider implementing caching for manifests
2. Optimize the file filtering logic in `ListIIIFFilesAttribute`
