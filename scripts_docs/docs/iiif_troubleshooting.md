# IIIF Troubleshooting Guide

This guide provides solutions to common issues encountered when working with IIIF in Zenodo RDM.

## Common Errors

### 1. "not enough values to unpack (expected 2, got 1)"

**Problem:**
```
ValueError: not enough values to unpack (expected 2, got 1)
```

**Cause:** Using incorrect format for IIIF manifest URL.

**Solution:** Always use the format `record:ID` in IIIF URLs. For example:
- Correct: `https://127.0.0.1:5000/api/iiif/record:202/manifest`
- Incorrect: `https://127.0.0.1:5000/api/iiif/202/manifest`

### 2. "File not found" from IIPServer

**Problem:**
```
/images/public/private_202_page-001.ptif is neither a file nor part of an image sequence
```

**Cause:** The PTIF file doesn't exist in the IIPServer container.

**Solution:**
1. Ensure the IIPServer container has the proper directories:
   ```bash
   docker-compose exec iipserver mkdir -p /images/public
   ```
2. Convert the original image to PTIF:
   ```bash
   python convert_to_ptif.py image.tif record_id
   ```
3. Use the setup script for automation:
   ```bash
   ./setup_iiif_for_record.sh record_id
   ```

### 3. "Invalid 'Accept' header"

**Problem:**
```
{"status": 406, "message": "Invalid 'Accept' header. Expected one of: application/ld+json"}
```

**Cause:** Inconsistent Accept header requirements between different endpoints.

**Solution:** Try these Accept headers:
- For manifest: `-H "Accept: application/ld+json"`
- For image info: `-H "Accept: application/json"`

## Checking IIIF Setup

To verify that IIIF is set up correctly for a record:

1. Check manifest existence:
   ```bash
   curl -k -H "Accept: application/ld+json" https://127.0.0.1:5000/api/iiif/record:ID/manifest
   ```

2. Check image info:
   ```bash
   curl -k "https://127.0.0.1:5000/api/iiif/record:ID:FILENAME/info.json" 
   ```

3. Check image access:
   ```bash
   curl -k "https://127.0.0.1:5000/api/iiif/record:ID:FILENAME/full/200,/0/default.jpg" -o thumbnail.jpg
   ```

4. Use the check_iiif.py script for comprehensive verification:
   ```bash
   python check_iiif.py ID
   ```

## IIPServer Diagnostics

To directly check the IIPServer:

1. Verify IIPServer is running:
   ```bash
   docker-compose ps iipserver
   ```

2. Check direct access to PTIF:
   ```bash
   curl "http://localhost:8080/fcgi-bin/iipsrv.fcgi?IIIF=/private_ID_FILENAME.ptif/info.json"
   ```

3. List files in IIPServer:
   ```bash
   docker-compose exec iipserver ls -la /images/public
   ```

## Automatic Setup

For convenience, you can use the automated setup script:

```bash
make setup-iiif RECORD=ID
```

This will:
1. Download all image files from the record
2. Convert them to PTIF format
3. Copy them to the IIPServer
4. Verify the IIIF manifest is accessible

## IIIF URL Formats

### Manifest URLs

The correct format for manifest URLs is:
```
https://127.0.0.1:5000/api/iiif/record:{record_id}/manifest
```

For example:
```
https://127.0.0.1:5000/api/iiif/record:202/manifest
```

### Image URLs

The correct format for image URLs is:
```
https://127.0.0.1:5000/api/iiif/record:{record_id}:{filename}/{region}/{size}/{rotation}/{quality}.{format}
```

For example:
```
https://127.0.0.1:5000/api/iiif/record:202:page-001.tif/full/200,/0/default.jpg
```

### IIPServer Direct Access

For direct access to IIPServer (bypassing Zenodo RDM):
```
http://localhost:8080/fcgi-bin/iipsrv.fcgi?IIIF=/private_{record_id}_{filename}.ptif/{region}/{size}/{rotation}/{quality}.{format}
```

For example:
```
http://localhost:8080/fcgi-bin/iipsrv.fcgi?IIIF=/private_202_page-001.ptif/full/200,/0/default.jpg
```

## How IIIF Works in Zenodo RDM

1. **File Storage**: Original files are stored in Zenodo RDM's storage system
2. **PTIF Conversion**: Original image files need to be converted to PTIF format
3. **IIPServer**: Serves image tiles from PTIF files
4. **IIIF Manifest**: Dynamically generated by Zenodo RDM based on record metadata
5. **Proxy Mechanism**: Zenodo RDM proxies image requests to IIPServer

## Debugging Tips

1. **Check File Existence**: Verify that the original file exists in the record
   ```bash
   python check_record.py RECORD_ID
   ```

2. **Verify PTIF Creation**: Check if PTIF conversion was successful
   ```bash
   docker-compose exec iipserver find /images -name "private_RECORD_ID_*.ptif"
   ```

3. **Test Direct IIPServer Access**: Bypass Zenodo RDM to test IIPServer directly
   ```bash
   curl "http://localhost:8080/fcgi-bin/iipsrv.fcgi?IIIF=/private_RECORD_ID_FILENAME.ptif/info.json"
   ```

4. **Examine Server Logs**: Check for error messages
   ```bash
   docker-compose logs iipserver
   ```

5. **Regenerate the PTIF**: If all else fails, try recreating the PTIF file
   ```bash
   make setup-iiif RECORD=RECORD_ID
   ```
